# Chapter I

# Introduction

Cloud computing has redefined enterprise infrastructure, allowing organizations to scale resources on demand. However, this agility comes with a steep cost: complexity. In massive industrial and corporate networks—where legacy operational technology often intersects with modern IT—tracking exactly "who opened what door" becomes an immense challenge.

A single misconfigured storage bucket or an overly permissive Identity and Access Management (IAM) role can expose an entire organization. Traditional perimeter security assumes a trusted internal network, but modern cloud security assumes the network is already hostile.

To combat configuration drift at an enterprise scale, security teams rely on automation. Cloud Security Posture Management (CSPM) acts as an automated auditor, continuously scanning the environment against strict industry standards.

This project simulates a critical mission within a large-scale corporate environment: you are tasked with deploying an automated auditing pipeline, filtering the noise of a massive infrastructure scan, and engineering the precise remediation steps to close the gaps. In the cloud, visibility is survival.

# Chapter IV

# Overview

Here are the things you need to know if you want to succeed in this assignment:

* You act as the **Auditor** evaluating a non-production cloud sandbox.
* You must utilize an open-source CSPM tool (such as **Prowler** or **Cloud Custodian**).
* The audit must evaluate the infrastructure strictly against the **CIS Benchmarks**.
* Enterprise scans are noisy. You will generate raw data, but you must filter this down to identify the **top 5 to 10 most critical misconfigurations**.
* Identifying the vulnerability is only half the job. You must also write the precise Infrastructure as Code (IaC) blocks or CLI commands required to **remediate** the specific findings.
* The entire process must be capable of running continuously on a schedule without manual intervention.

# Chapter V

# Global rules

You have to write **one automated pipeline script** that complies with the following rules:

* **Manual clicking through a cloud console is forbidden!** All actions must be automated.
* Your pipeline execution script must take the following arguments:
`target_environment` `compliance_framework` `severity_filter` `output_format`
◦ `target_environment`: The identifier or profile name of the cloud account to be audited (e.g., `default`, `sandbox-01`).
◦ `compliance_framework`: The security standard to audit against. Must support at least `cis`.
◦ `severity_filter`: The minimum severity level to include in your final filtered report. Must accept `CRITICAL`, `HIGH`, `MEDIUM`, or `LOW`.
◦ `output_format`: The format of the final consolidated report. Must accept `html` or `csv`.
* If the pipeline encounters an API rate limit from the cloud provider, it must implement an exponential backoff strategy rather than crashing.

```
Reminder: All arguments are mandatory. Reject invalid inputs such
as unsupported frameworks or invalid severity levels with a clean 
error message.

```

# Chapter VI

# Mandatory part

```
Program Name: cloud_audit
Files to Submit: pipeline.py / pipeline.ps1, remediation_playbooks/, 
                 execution wrapper (Makefile or run script)
Arguments: target_environment compliance_framework severity_filter 
           output_format
External Functions: Cloud provider CLIs (AWS CLI, Azure CLI), 
                    CSPM tools (Prowler), standard library 
                    JSON/CSV parsers, cron/Task Scheduler.
Description: Automated CSPM execution, filtering, and remediation.

```

The specific rules for the mandatory part are:

* **Baseline Scanning:** The pipeline must successfully authenticate to the cloud environment using read-only permissions and execute a full CSPM scan.
* **Noise Reduction:** The pipeline must parse the raw output (usually JSON) generated by the CSPM tool. It must filter out `PASS` results and extract only the failed checks that meet or exceed the `severity_filter` argument.
* **Remediation Playbooks:** For every `CRITICAL` or `HIGH` vulnerability type identified by your filter, you must provide a corresponding remediation playbook file inside the `remediation_playbooks/` directory.
* These playbooks must contain the exact CLI command or Terraform/Ansible code block required to fix the vulnerability (e.g., enabling encryption on an S3 bucket).


* **Executive Reporting:** The pipeline must compile the filtered findings into a clean, human-readable file specified by the `output_format` argument.
* **Automation Proof:** You must provide documentation or a script configuration (like a cron job or Windows Task Scheduler XML) proving that this pipeline can be executed automatically on a daily schedule.

Example of a pipeline execution:

```powershell
> ./pipeline.ps1 sandbox-01 cis CRITICAL html

[INFO] Authenticating to sandbox-01...
[INFO] Executing CSPM scan against CIS benchmarks...
[INFO] Scan complete. 1432 checks performed.
[INFO] Filtering results for CRITICAL severity...
[WARN] 3 CRITICAL misconfigurations found:
       - cis-2.1.1: Storage bucket 'corporate-data-backup' is publicly accessible.
       - cis-1.14: Root account access keys exist.
       - cis-3.8: CloudTrail logging is disabled.
[INFO] Generating HTML report...
[INFO] Report saved to ./reports/audit_sandbox-01_CRITICAL.html
[INFO] Relevant remediation playbooks are available in ./remediation_playbooks/
```
